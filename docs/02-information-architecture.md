| 路由/入口 | 内容 | 主要下一步 |
| --- | --- | --- |

| `/work` | 三个商业工程案例，按仿真闭环、编辑系统、尺度协同排序 | `/work/[slug]` |

实验室固定 slug：`gpuview`、`dreamscape`、`mistloop`、`imageplayer`。全局导航为工程案例、实验室、关于、博客、简历；底部提供 GitHub、CSDN、联系方式。第一版不展示无内容的文章路由；本地 MDX 内容方案在有文章时复用。

## 首页顺序

| 顺序 | 访客需要确认的事 | 呈现方式 |
| --- | --- | --- |
| 定位 | 是谁，有什么经验，在找什么机会 | 双栏首屏，左文案右仿真示意 |
| 经验 | 是否持续参与复杂产品研发 | 三项简短经验摘要，不用技能百分比 |
| 案例 | 做过哪些困难问题，具体负责什么 | 轨道主案例 + 两个辅助案例 |
| 能力 | 技术关键词能否对应真实证据 | 四组能力，每组链接对应案例 |
| 实验室 | 能否把个人想法做成可运行作品 | 两个有实际截图的主卡 + 两个紧凑入口 |
| 经历与联系 | 经验时间线及如何联系 | 简短经历、电话、邮箱、简历入口 |

## 详情模板

商业案例统一包含：问题和约束、个人职责、重新绘制的架构/数据流、关键取舍、测试与验证、结果和边界、相关案例。原简历未提供具体数字的结果保留定性表述。无可公开商业截图时，使用明确标记的架构示意，不暗示为公司实机。

个人项目统一包含：项目类型、已有功能、本人工作范围、实现路径、截图来源、代码与数据边界、验证记录、链接状态、许可证情况。区分 README 的“已实现”和“后续计划”。游戏外链在点击后打开独立页，不在首页自动加载游戏或音频。

## 后续内容接口

阶段二使用一份本地项目数据：`slug`、标题、类型、职责、技术栈、图片及说明、正文、源码/演示链接及其核验状态。商业案例和个人项目共用展示字段，分别保留验证和证据说明。构建时读取，不在访客浏览时抓取 GitHub/CSDN。

首版 `/resume` 只有一份主简历。多版本路由留待实际岗位内容存在后添加，不复制空壳版本。每个可索引详情页独立设置标题、描述、canonical、分享图；sitemap 不包含尚未发布的栏目。

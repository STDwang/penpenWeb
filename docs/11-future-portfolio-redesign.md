# 交互式个人网站改版方案与实施记录

## 目标

让访客在首屏立即看清「王帅鹏 / C++ 与仿真平台工程师」的定位，并通过明确入口选择工作成果、个人项目、关于与联系。作品的浏览由连续纵向下拉改为一次聚焦一个案例的轮播；人物形象与板块切换共同构成网站的视觉线索。

## 现状与取舍

- 原首页包含多个连续纵向区块，工程与个人作品虽已有横向滚动卡片，但首屏无法直接切换整个内容类别。
- 原卡片在小屏仍需阅读较长内容；新的立体卡片轮播让相邻项目可见，点击、方向键或触摸滑动切换，标题与详情入口跟随当前卡片。
- 保留 Next.js 静态导出和现有案例、图片归属说明、简历及详情路由。深度案例和完整简历属于长文阅读内容，仍允许正常纵向阅读；一级内容发现不依赖下拉。
- 视觉使用深石墨、冷白、少量青绿，减轻玻璃与多色光效；标题采取大字和中英文字体层级，形成杂志式留白。

## 交互方案

1. 首页四个常驻入口：主页、工作成果、个人项目、关于与联系。点击立即切换，不自动轮转，也不劫持滚轮。
2. 人物在每个首页板块都占较大面积，镜头从半身转到近景；板块或项目切换触发转身、倾身、抬头的过渡，随后保持目标姿态。角色上的按钮可进入下一板块。
3. 工作成果和个人项目复用立体卡片轮播：上一项、下一项、点选相邻卡片、左右方向键、触屏横划、详情/源码/演示入口。图片保留原始来源说明，不把产品整体误写为个人独立成果。
4. `prefers-reduced-motion` 下关闭人物与板块动画。无 JavaScript 时提供普通链接，仍可访问项目详情。
5. 详情页保持已有目录、灯箱、相关案例与原图入口，用于读证据和技术说明。

## 已实施

- `code/src/components/home-stage.tsx`：首页四板块、人物与内容联动、角色按钮、网址片段直达。
- `code/src/components/future-character.tsx`：Three.js 场景、弯曲网格、连续镜头和姿态过渡；目前使用已确认图片作为网格贴图。
- `code/src/components/rigged-character.tsx` 与 `code/public/models/future-self-free-rig.glb`：免费骨骼动画实验。首页“试用骨骼动画原型”按钮可切换到真实关节模型；工作成果抬臂、个人项目转身，项目切换也会触发动作，结束后保持姿态。默认仍显示已确认的人物形象。
- `code/src/components/feature-carousel.tsx`：工程与个人项目共用轮播。
- `code/src/app/future.css`：全站色彩和排版、新首页、轮播、响应式及减少动态效果。
- `code/src/app/page.tsx`、`work/page.tsx`、`lab/page.tsx`：一级页面改版。
- `code/public/images/future-self-approved.webp`：依据用户确认图片生成的站点素材；原始补拍照片未加入站点。
- `code/tests/site.spec.ts`：改为验证板块入口、角色切换、轮播、详情、移动端和无脚本访问。

## 验收口径

- 1440、768、390 像素宽度下，首页角色、四个入口和当前板块清晰可见；无横向溢出。
- 工程与个人项目能够通过按钮和直接选择切换，标题、图片、职责与跳转同步更新。
- 角色在四个首页板块都保持大幅；板块或项目切换后停在对应镜头姿态；减少动态效果设置下无持续动画。
- 所有原详情路由与 PDF 简历可访问，来源和职责范围说明保留。

## 边界

默认角色是透明人像贴在可变形的 Three.js 网格上，具备镜头和网格动作，但没有独立肩、肘、手指骨骼，**不能满足最终的真实抬手和定格姿态要求**。切换用的两张静态姿态图没有加入网站。

免费实验角色由 [Ara 3D Gen](https://github.com/olatunde85/3d-gen) 浏览器端生成，GLB 约 6.7 MB，含 69 根骨骼和 Idle、Wave、左右转身、Cheer 动画；代码 MIT、MakeHuman 基础素材 CC0、动作来自 CMU 动作捕捉库。它证明了真实关节动画、板块联动和动作完成后定格可在本网站运行。**实验模型的脸并不像用户，不能作为最终“我”的 3D 人物。** 浏览器端生成过程中没有上传用户照片。尝试用已确认形象编辑皮肤 UV 贴图时，图像生成服务的自动安全审核因原始皮肤贴图拒绝了请求；没有尝试绕过。

后续需要一份与用户形象一致、已绑骨的 GLB/VRM，才可用 `three-vrm` 的骨骼控制或 Three.js 的动画混合器实现「入场动作→停在目标姿态」。已生成本地全身 A-pose 参考图 `previews/future-self-rig-reference.png`，尚未上传任何 3D 建模服务。Meshy 官方的 Auto-Rigging 要求完整、四肢清晰的双足人形；用户当前的半身图不适合作为直接绑骨输入。

2026-10-26 建模方向更新：用户明确不满意既有 v035 的头部。新的头部以本次生成的白膜正面、侧面及斜侧视图为造型主参考，以本人照片校验辨识特征。私有建模项目已建立独立的可雕刻头部工程、照片与概念图关键点、可旋转脸部导向面和对照图；当前仍是底模，五官与发型尚未通过相似度验收。网站不得把 v035 头部或这批中间产物作为最终人物替换；待新头部、分层头发、绑定及动作测试通过后再接入。

本机 NVIDIA RTX 3060 Laptop 仅有 6 GB 显存，调研到的本地全流程照片转模型方案分别以 12 GB 或 16 GB 以上为目标。用户明确选择暂不使用付费服务；本轮没有向第三方上传用户照片，也没有下载大模型。Ara 的源码压缩包单独放在 `E:\AiStudy\ara-3d-gen`，网页端完成了模型生成与导出，无需下载约 420 MB 的完整本地素材包。

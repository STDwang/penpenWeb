# 个人网站 UI 与交互审视（2026-10-27）

## 现状与本轮已完成

- 已在顶部导航加入「主页」。在首页作品视图点击后返回 `#intro`，在其他页面点击后返回首页；移动端入口位于展开的菜单中。
- 首页人物由五张 1672×941 的白色场景图和五张同尺寸的黑色场景图组成。原先首页进入时请求同主题全部五张图（白色约 8.05 MiB，黑色约 8.54 MiB）；现在先请求首页和展开双臂所需的两张，并在进入其他场景时再请求对应画面。
- 场景切换曾将非活动画面设为 `blur(5px)`，再用 0.75 秒去除模糊。这个过程会让脸部在过场中显得发软；现已去除模糊，当前帧优先加载。

## 按影响排序的发现

| 优先级 | 观察 | 对体验的影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 放大运镜最高达到 1.54 倍，而整幅源图宽度只有 1672 像素。脸部只占其中一部分。 | 镜头靠近眼镜、手表时，脸部与镜框的真实细节会被放大，CSS 无法补回源图中没有的纹理。 | 以现有人物为身份基准，制作更高分辨率、构图和动作一致的成套场景帧；逐帧核对眼睛、脸型、镜框和房间透视，确认后再替换。保留现有图作为回退。 |
| P1 | 桌面首页大标题的末端跨到白色衣服和明亮地面上；工作成果卡片的半透明文案层也叠在复杂图像上。 | 文本对比会随背景位置变化，初看精致，但长时间阅读不稳定。 | 给文本所在区域加局部、方向性的轻微明暗遮罩；调整卡片文案层透光率，并逐项检查两种主题下正文和按钮的对比度。 |
| P1 | 390px 移动端虽然完整露出三张卡，但两侧卡缩到 0.62 倍，副标题和详情链接实际显示很小。 | 侧卡可以看见，却难以阅读或准确点击。 | 保持三卡完整露出；侧卡改为紧凑排版，保留图片、标题和每卡的详情入口，点击卡身先聚焦到中间。中心卡继续显示完整介绍。 |
| P1 | 卡片悬浮倾斜随鼠标位置改变，但基础 `transform` 过渡为 0.65 秒。高光覆盖在文字上。 | 手势反馈略滞后，高光经过文字时会影响阅读。 | 悬浮角度控制在约 2–3°，鼠标跟随用更短的响应，轮播换位保留较长的缓动；高光只作用于玻璃边缘与图像区域，键盘聚焦给出等效反馈。 |
| P2 | 移动端首页信息卡固定延伸到页面底部，正文结束后仍留较大空白。 | 画面像未填满的面板，人物身体被过早盖住。 | 让信息卡按内容决定高度并贴近底部，短屏时允许内部滚动，保留脸部和肩部的展示空间。 |
| P2 | 目前转场由静态场景帧、缩放与闪光叠加组成。脸部、衣服和房间在相邻帧之间会有细节跳变。 | 放大时更像图片切换，和用户希望的连续专业运镜还有距离。 | 先统一全部关键帧的人物与场景，再设计每条相机路径的起止位置、时长和遮挡关系；若要真正连续的镜头运动，应使用同一人物与空间制作视频或深度分层素材。 |

## 建议实施顺序

1. **清晰度与可读性**：先确认人物高分辨率母图和十张同主题关键帧；在现有页面完成桌面标题、卡片正文及黑白主题的对比度处理。验收时查看 1440px 桌面和 390px 手机的脸部、眼镜及卡片文字。
2. **卡片交互**：重做移动端侧卡信息密度；统一鼠标悬浮、键盘聚焦和触摸选择的反馈，并检查每张卡的详情入口都容易触达。
3. **镜头与性能**：基于确认后的素材调整运镜曲线与场景衔接，再输出压缩后的静态资源；检查首次进入、主题切换和快速连续点击，避免空白画面或转场中途跳帧。

每一步都分别提供桌面与移动端的白色、黑色主题预览，再进入下一步。保留 `prefers-reduced-motion` 下的直接切换路径。

## 当前素材的边界

本轮的滤镜与请求顺序优化能减少“看起来模糊”和首次加载时的竞争请求；它不能把 1672×941 的整幅图变成高清面部特写。真正的细节提升需要新的高分辨率、身份一致的源图，且不能只对脸部局部贴图，否则会重新出现照片剪裁感。
